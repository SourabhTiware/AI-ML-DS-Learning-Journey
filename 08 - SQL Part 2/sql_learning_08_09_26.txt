1. What is a SQL JOIN?

A JOIN is used to combine rows from two or more tables based on a related column between them.

For example, consider two tables:

Employees
employee_id	name	department_id
1	Adam	101
2	Bob	102
3	Charlie	103
4	David	NULL
Departments
department_id	department_name
101	IT
102	HR
104	Finance

The common column is:

department_id

SQL JOINs allow us to combine these tables in different ways.

2. INNER JOIN

INNER JOIN returns only the records that have matching values in both tables.

Syntax
SELECT *
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;
Result
Employee	Department
Adam	IT
Bob	HR

Charlie is excluded because department 103 does not exist in the departments table.

David is excluded because he does not have a department.

Key Concept
Employees ∩ Departments
     Only Matching Data

INNER JOIN = Only common records from both tables.

3. LEFT JOIN / LEFT OUTER JOIN

LEFT JOIN returns:

All records from the left table.
Matching records from the right table.
NULL if no match exists.

LEFT JOIN and LEFT OUTER JOIN mean the same thing.

Example
SELECT employees.name, departments.department_name
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id;
Result
Employee	Department
Adam	IT
Bob	HR
Charlie	NULL
David	NULL
Key Concept
All LEFT table records
+
Matching RIGHT table records
4. RIGHT JOIN / RIGHT OUTER JOIN

RIGHT JOIN returns:

All records from the right table.
Matching records from the left table.
NULL where no match exists.

RIGHT JOIN and RIGHT OUTER JOIN mean the same thing.

Example
SELECT employees.name, departments.department_name
FROM employees
RIGHT JOIN departments
ON employees.department_id = departments.department_id;
Result
Employee	Department
Adam	IT
Bob	HR
NULL	Finance

Finance is included even though no employee belongs to department 104.

Key Concept
Matching Records
+
All RIGHT table records
5. FULL OUTER JOIN

A FULL OUTER JOIN returns:

All matching records.
Unmatched records from the left table.
Unmatched records from the right table.

Conceptually:

LEFT JOIN
   +
RIGHT JOIN
Standard SQL Syntax
SELECT *
FROM employees
FULL OUTER JOIN departments
ON employees.department_id = departments.department_id;
Result
Employee	Department
Adam	IT
Bob	HR
Charlie	NULL
David	NULL
NULL	Finance
Important Note

Not every database supports FULL OUTER JOIN directly. For example, MySQL traditionally requires simulating it using LEFT JOIN + RIGHT JOIN with UNION.

Example:

SELECT *
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id

UNION

SELECT *
FROM employees
RIGHT JOIN departments
ON employees.department_id = departments.department_id;
6. CROSS JOIN

CROSS JOIN returns the Cartesian product of two tables.

Every row from the first table is combined with every row from the second table.

Example
SELECT *
FROM employees
CROSS JOIN departments;

If:

Employees = 4 rows
Departments = 3 rows

Then:

4 × 3 = 12 rows

will be generated.

Example Use Case

Suppose:

Colors
Red
Blue
Green
Sizes
S
M
L

Using CROSS JOIN:

Red   - S
Red   - M
Red   - L
Blue  - S
Blue  - M
Blue  - L
Green - S
Green - M
Green - L

Important: Be careful with CROSS JOIN on large tables because the number of rows can grow extremely quickly.

7. SELF JOIN

A SELF JOIN means joining a table with itself.

It is useful when records within the same table have relationships.

Example: Employee and Manager
id	name	manager_id
1	John	NULL
2	Adam	1
3	Bob	1
4	Charlie	2

Here, manager_id refers to another employee's id.

Query
SELECT 
    e.name AS employee,
    m.name AS manager
FROM employees e
LEFT JOIN employees m
ON e.manager_id = m.id;
Result
Employee	Manager
John	NULL
Adam	John
Bob	John
Charlie	Adam
Key Concept
Same Table
    ↓
Joined With
    ↓
Same Table

Aliases such as e and m are necessary to distinguish between the two references.

8. Exclusive LEFT JOIN

An Exclusive LEFT JOIN returns only the records from the left table that do not have a match in the right table.

This is commonly achieved using LEFT JOIN with WHERE ... IS NULL.

Example
SELECT employees.*
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id
WHERE departments.department_id IS NULL;
Result
Employee	department_id
Charlie	103
David	NULL
Meaning
LEFT TABLE
MINUS
MATCHING RECORDS

This is also called a Left Anti Join conceptually.

9. Exclusive RIGHT JOIN

An Exclusive RIGHT JOIN returns only the records from the right table that do not have a match in the left table.

Example
SELECT departments.*
FROM employees
RIGHT JOIN departments
ON employees.department_id = departments.department_id
WHERE employees.department_id IS NULL;
Result
Department
Finance
Meaning
RIGHT TABLE
MINUS
MATCHING RECORDS

This is conceptually called a Right Anti Join.

11. Comparison of All JOIN Types
JOIN Type	Returns
INNER JOIN	Only matching records from both tables
LEFT JOIN	All left records + matching right records
RIGHT JOIN	All right records + matching left records
FULL OUTER JOIN	All records from both tables
CROSS JOIN	Every possible combination
SELF JOIN	A table joined with itself
Exclusive LEFT JOIN	Only unmatched records from the left table
Exclusive RIGHT JOIN	Only unmatched records from the right table
12. Practical Example

Consider a hospital database.

Patients Table
patient_id | patient_name | doctor_id
Doctors Table
doctor_id | doctor_name
INNER JOIN

Find patients who have assigned doctors:

SELECT p.patient_name, d.doctor_name
FROM patients p
INNER JOIN doctors d
ON p.doctor_id = d.doctor_id;
LEFT JOIN

Find all patients, including those without assigned doctors:

SELECT p.patient_name, d.doctor_name
FROM patients p
LEFT JOIN doctors d
ON p.doctor_id = d.doctor_id;
Exclusive LEFT JOIN

Find patients without assigned doctors:

SELECT p.patient_name
FROM patients p
LEFT JOIN doctors d
ON p.doctor_id = d.doctor_id
WHERE d.doctor_id IS NULL;

This type of query is highly useful in real applications for finding missing relationships or incomplete data.

Key Takeaways
SQL JOINs are used to combine related data from multiple tables.
INNER JOIN returns only matching records.
LEFT JOIN keeps all records from the left table.
RIGHT JOIN keeps all records from the right table.
FULL OUTER JOIN includes records from both tables.
CROSS JOIN creates every possible row combination.
SELF JOIN joins a table with itself.
Exclusive joins help identify unmatched records.
Table aliases make JOIN queries easier to read and are essential for self joins.
JOINs are fundamental for working with normalized relational databases.
Important Practical Understanding

The main concept from today's learning is:

Multiple Tables
      ↓
Related Columns
      ↓
      JOIN
      ↓
Combined Data

Understanding JOINs is extremely important for Data Analysis, Data Science, Backend Development, and Machine Learning, because real-world data is rarely stored in a single table. Most production databases distribute related information across multiple tables, and JOINs are required to combine that data for analysis.
